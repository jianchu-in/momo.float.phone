# 面对面、多人配图与反查岗收藏：待实施修改清单

状态：需求讨论记录，功能尚未开始实施。本次提交只增加本文件与 PR 中的说明，不代表下列功能已完成或测试通过。待用户明确说“开始”后再实施功能修改。

## 1. 面对面单人和多人组选择

- [ ] 参考剧情 APP 的选择方式，分别展示单人角色与已保存的多人组。
- [ ] 多人组可创建、命名、保存和选择；再次进入时恢复该组的对话记录与上次地点。
- [ ] 单人与不同多人组各自保存记录，保留已有记录、主线、分线及独立见面的正确归属。
- [ ] 切换要编辑的角色，不改变当前多人组成员、当前对话或共同地点。

## 2. 多人面对面地点与立绘修复

### 已报告的问题

选择多个角色后，地点被限制为第一个角色的地点，无法正常更换。剧情推进到第二个角色发言时，其立绘未正常显示。

### 目标行为

- [ ] 多人地点选择包含组内角色的可用地点及通用地点，不受首位角色限制。
- [ ] 同名地点标明归属，保存时准确区分具体地点，避免只凭“客厅”等名字错误匹配。
- [ ] 选定地点作为本次见面的共同地点；切换发言人时保持地点和背景一致，实际换场后再更新。
- [ ] 地图进入、直接开启见面、继续旧对话都能恢复正确的地点关联及原有氛围音行为。
- [ ] 当前发言角色的台词、语音与立绘同步切换，处理异步加载和多人顺序播放，避免 A 的画面配 B 的台词。
- [ ] 优先使用该角色在当前地点匹配的立绘，缺少匹配时使用该角色自己的默认立绘或明确的头像/缺素材提示，不错用其他角色素材。
- [ ] 验证各角色的情绪立绘、拖动位置与缩放互不串用；切换已有素材不额外触发生图。

## 3. 面对面统一参数与设置预设

参数设置统一；场景/立绘素材与语音按角色管理。多人设置页面提供具体角色选择，明确当前正在编辑谁的素材和语音。

- [ ] 增加设置预设的保存、命名、选择和应用，用于一键套用一整套设置数值。
- [ ] 预设范围从“生成 CG 图（新画面）”区域开始，覆盖其下的生成要求与对话外观设置。
- [ ] 公共参数不因发言角色切换而交替生效，也不继续隐式由第一个角色决定。
- [ ] 应用预设与编辑某位角色的素材/语音分清作用范围，保留每个角色自己的素材与音色绑定。
- [ ] 保存后重开、切换多人组以及备份恢复后，设置和预设仍正确生效。

| 设置区域 | 预设覆盖内容 |
| --- | --- |
| CG 设置 | 开关、生图间隔、自动展示轮数、跳过 NSFW、CG 额外要求、人物参考来源等设置值 |
| 生成要求 | 生成格式、对话符号、额外提示词、回复长度与自定义字数、语音开关、默认 NPC、记忆开关 |
| 对话外观 | 气泡颜色、不透明度、文字颜色、字号 |

角色参考图按实际出镜角色的绑定读取；统一预设不应让某个角色的图片被误当成另一个角色的参考。

## 4. 统一使用真实收藏，取消新增相册

- [ ] 不新增桌面相册或反查岗“我的相册”，取消“多选后添加到我的相册”这一套独立收录流程。
- [ ] 使用已有收藏作为唯一收录体系，补齐聊天、栖所、面对面、剧情来源图片的收藏入口与来源分类/标签。
- [ ] 保留面对面已有“生图成品”入口，支持将生成图片加入收藏，沿用已有完整预览、描述与原图下载功能。
- [ ] 收藏与原来源共用原图；生图成品记录和收藏记录可独立存在，不因增加一个查看入口再复制原图。
- [ ] 已收藏图片在删除原聊天、剧情或来源成品后仍可查看；取消收藏不能误删其他位置仍在使用的原图。

## 5. 反查岗“我的收藏”：轻量展示与简化互动

在“我的手机”反查岗中增加“我的收藏”APP，读取同一份真实收藏。外部收藏 APP 保持完整管理界面，反查岗使用轻量查看界面。

### 展示方式

- [ ] 进入后直接显示最近的、允许查看的收藏，不强制逐层选择“来源 → 角色/组 → 列表”。
- [ ] 卡片只展示来源、相关角色/组、图片缩略图或约两行文字摘要，点击后展开完整内容。
- [ ] 顶部保留“全部/图片/文字”等简洁入口；角色、组、来源和标签筛选放入可选筛选按钮。
- [ ] 图片列表使用三列九宫格，支持点击放大；文字和整段对话沿用真实收藏卡片与展开内容。
- [ ] 内容限定为当前用户身份、账号和允许该角色查看的范围，不将其他账号、身份或未授权内容混入。
- [ ] 外部真实收藏的变化能反映到该入口，不生成虚构收藏。

### 模拟过程

- [ ] 默认流程为“进入收藏 → 看当前一屏 → 挑少量条目打开 → 边看边反应 → 返回”；必要时可继续翻阅或筛选。
- [ ] 通常先查看少量条目，例如 2～3 条，并设置查看/翻页上限，避免长收藏无限浏览。
- [ ] 保留简单的点击、展开、停留、返回操作，减少无意义的层层筛选、长距离滚动和重复模型调用。
- [ ] 文字依据实际展示的内容反应；图片页或放大图片按实际可见区域截图，交给支持识图的模型。
- [ ] 模型仅接收本次实际可见的内容；没打开的详情、没展开的聊天不能描述成已经完整看过。
- [ ] 查看记录区分缩略图浏览、打开详情和展开内容，沿用已有查岗记录、回放与记忆流程。
- [ ] 识图截图按临时请求数据管理并及时释放；回放沿用现有媒体去重和容量控制，避免另存多套完整图片。
- [ ] 识图不可用时给出真实提示；不根据截图虚构语音或视频中未被实际获取的内容。

## 6. 多人剧情与多人面对面 CG 的人物参考图

新增“按本张画面实际出镜角色使用参考图”的可选生图方式，保留纯文字生图选择。

### 人物选择与参考绑定

- [ ] 写剧情/面对面对话的文字模型在原本同一次回复中输出画面描述、出镜角色名单和用户是否入镜，不额外增加独立的文字规划请求。
- [ ] 出镜名单依据实际发生的剧情和镜头构图，不直接等同于多人组全员、首位角色或本轮发言名单。
- [ ] 程序校验角色编号属于本次对话，按每位出镜角色的已有绑定读取各自参考图，不让模型猜图片文件的归属。
- [ ] 发给生图模型的参考图标明人物身份，并与描述中的人数、位置、动作和朝向对应。
- [ ] 未入镜角色不附人物参考图，也不在画面描述中额外补入其外貌；环境空镜不附角色参考图。
- [ ] 用户参考图按用户实际入镜情况和相关设置决定；第一视角不自动等同于用户本人露脸。
- [ ] 场景参考优先使用不含人物的背景，避免场景素材里原有的人物被误带入新图。
- [ ] 缺少人物参考图、图片不可读或当前通道在本项目中不支持参考图时明确提示，允许选择纯文字方式，不拿别人的图替代。
- [ ] 画面描述、出镜名单与参考选择随该张图及回复版本保存；重试/重新生成可查看、调整，后续剧情变化不改写旧图的参考选择。

| 实际画面 | 使用的人物参考图 |
| --- | --- |
| A 的单人近景 | A |
| A、B 同框，C 在镜头外 | A、B |
| 只有环境或物件 | 无人物参考图 |

当前代码检查发现：多人剧情配图明确强制纯文字；面对面多人 CG 主要使用最后发言角色的参考图加场景图。以上为待补齐的能力，不应把现有单人参考设置描述成已支持完整多人参考。

## 7. 图片存储、数据体积与备份恢复

- [ ] 修正已发现的面对面 CG 双写路径：通用生图服务写入媒体缓存后，面对面又将同一结果写入素材库。需核对有效引用后复用原图，避免新增重复文件。
- [ ] 生图、成品展示、收藏共用原图，逻辑上的独立保留通过记录和引用实现。
- [ ] 保持既有图片、消息、收藏与回放兼容，验证删除和引用释放，不能仅凭“看似缓存”就清理仍有效的数据。
- [ ] 多个生图通道/方案主要增加配置参数，不应因通道数量而复制整套参考图或图片库。真正的媒体体积与实际保存的参考图、生成图及回放有关。
- [ ] 本地存储复用与备份媒体去重分别验证，不能用“压缩包已去重”代替“运行时仅保存一份原图”的验证。
- [ ] 继续使用已有“收藏”备份选项，不新增“我的相册”备份模块。
- [ ] 单独勾选收藏备份时，应带齐独立恢复所需的原图和媒体，不强制同时勾选原聊天/剧情/素材模块。
- [ ] 新增多人组、统一设置预设及其需要的参考信息纳入现有备份体系，恢复后保持归属和引用有效。
